Indian Creator Lab

YouTube Data API · SQLite · snapshot tables · pandas · scikit-learn · Streamlit

A watchlist of 100 Indian creators was a moving target: view counts change, and a one-time scrape cannot show a trend. I ingested the YouTube Data API into SQLite with a video key and a snapshot grain — views, likes, and comments captured over time, about 3,500 videos. Engagement is (likes + comments) / views. Outlier is this video against that creator’s median, so a small channel is not ranked against a large one. Streamlit is the serving layer: score a draft title and cut, return a view range, and show the nearest videos already in the table.

How I treat data

Store snapshots, not a single scrape. Define grain before you write the query. Prefer a rate against a baseline over a raw total. If a generator can invent a column name, the data product is unfinished. A view that does not change a decision is decoration.
